## What this says about where things live

Observations for the next step (N29), not decisions:

- Three existing systems carry most rows: GitHub (state, queue, identity, approvals, log), Claude Code with Remote Control (reaching sessions, notifications, hooks) and devvm (separation, enrolment). What the needs add to them is mostly configuration that spans projects and machines: label names, timers, hooks, settings text, briefs. That is the thing the principal named as having no home (2026-11-24): "managing multiple agents, token management for agents etc feels like it doesn't quite fit anywhere. It is not modama, not a skill, not a devvm".
- If GitHub's protected branches and environments carry N40 to N42, GitHub holds the credentials and binds each approval to its act, and the authorised officer shrinks to workflows and a policy for them. The principal the same day: the officer "sounds like it may need a separate repo to separate it from the rest" (as R5 of 2026-11-16). Both wait for the security analysis.
- One inbox repository would serve three needs at once: ideas (N10, N12), exceptions (N32) and what has no workstream yet; the record of 2026-11-16 calls it the portfolio headquarters (R8, R14).

## For the Team plan's Owner

The features the table would use, each with a switch or a condition on a Team plan (requirements 2.9, deferred until the design names them): Remote Control (off until an Owner switches it on); unattended runs on a timer under the Team login; Artifacts (on by default; sharing outside the organisation off); Claude Approvals (public beta, billed as usage credits). Not needed as things stand: channels, cloud scheduled tasks, a second seat.
